## Deferred (vetted this pass, not planned in this batch)

- **Coach storage cluster** (`coach.ts:50-54,75-87` + `controller.ts:156,181` + `app.tsx:47-59` + `ActionBar.tsx:100-101`) — three related defects worth one plan: (a) non-atomic read-merge-write on the single coach key races the unawaited `recordAssign` against `tryShowTip` on every pointer assign — last writer wins, losing either the decay counter or the once-only tip; (b) `tryShowTip` consumes the tip in storage before the caller knows it can still display — a sub-roundtrip hover permanently burns the one-time "first-hover" tip unseen, and ActionBar's count tooltip has no staleness guard at all (can appear after mouse-leave and stick); (c) 3-4 storage IPC round-trips per post-hover, ≥1 forever after decay. M effort.
- **No Preact error boundary** (zero `componentDidCatch` in src) — a render throw in a per-tweet overlay propagates out of a signal notification; in the select-mode click path this happens AFTER `preventDefault`+`stopImmediatePropagation` (`main.tsx:218-220`), so the user's click on a post is silently swallowed. Wrap App root + overlay roots. S-M.
- **Picker background-refresh race** (`picker-controller.ts:112-120`) — the silent `force:true` refresh can swap/shrink/reorder the list mid-keyboard-navigation; plan 014 makes highlight and Enter agree, but the underlying mid-navigation swap (freeze list while open, or reconcile activeIndex by id) remains. S-M.
- **Modal focus traps** (`WelcomeCard.tsx:19-23`, `ShortcutsSheet.tsx:32-36`; rule `react-doctor/prefer-html-dialog` — real here) — `aria-modal="true"` with no focus move-in/trap/restore; native `<dialog>.showModal()` is the canonical fix for these two true modals. S-M.
- **Selection loop has no SR feedback** (`main.tsx:207-223`, `ActionBar.tsx:40-58,98-112`) — selects/deselects and run progress ("Adding 3 of 12…") announce nothing; builds on 015's live regions. S-M.
