Architecture review — Lasso

2026-06-15 · deepening opportunities

A mature, comprehensively-tested codebase. The friction is not missing tests — it is shallow modules whose knowledge has leaked into copies. Three candidates below; each turns scattered, hand-synced logic into one deep module behind a small interface.

module seam leakage / duplication deep module now-internal (was a module)
Candidate A

Collapse the DOM-activation primitives into one deep module

Strong in-process · main-world bridge

src/core/x-client/caret-actions.ts · src/content/main-world.ts · src/core/x-client/dom-page-driver.ts

Before — three copies, hand-synced
After — one deep activation module
Problem

The synthetic pointer→mouse→click sequence is copied verbatim in isolatedActivate and main-world activate; the bridge protocol is mirrored as untyped postMessage with channel constants redefined in both files; dom-page-driver clicks with naive .click() — the exact path the others were written to avoid.

Solution

One module exposes activate(el) (bridge first, synthetic fallback) and waitForDom(pred); the bridge message shape is defined once and shared by both worlds; caret-actions and dom-page-driver consume it.

Wins
  • ▪ locality: "click X reliably" lives in one module
  • ▪ DOM backend gets robust activation — latent gap closed
  • ▪ leverage: one activate, three callers
  • ▪ bridge protocol typed, defined once
  • ▪ interface is the test surface: pin the sequence once
  • ▪ two real adapters: bridge + synthetic fallback
Deletion test: remove it → the synthetic sequence, scroll-when-offscreen, bridge handshake, and MutationObserver wait reappear across all three files. Complexity concentrates here. It earns its keep. Constraint for the grilling: the two scripts run in different worlds (MAIN vs ISOLATED), but that is a runtime fact — Vite inlines a shared import into both bundles, so the seam is buildable.

Problem

"Authenticated same-origin x.com call → typed XApiError" is written three times. authHeaders is byte-identical in all three; the status→error mapping is re-implemented in each — and the copies have drifted (GraphQL's 429 path drops resetAt).

Solution

One transport attaches the session headers + credentials:"include", parses the body, and throws the typed error. The v1.1 vs GraphQL code tables become a small classify argument, not a re-implemented ensureOk.

Wins
  • ▪ locality: headers + resetAt + status map in one place
  • ▪ the resetAt drift fix lands once, covers every backend
  • ▪ leverage: one transport, every X HTTP call site
  • ▪ interface is the test surface: map errors against one module
  • ▪ backends shrink to path + params + classify
  • ▪ contract test already pins behaviour across backends
Deletion test: remove it → authHeaders, credentials:"include", the 429/401/403 mapping, and resetAt parsing reappear in all three modules. Concentrates complexity. Earns its keep.
Candidate C

Deepen tweet targeting into a testable module

Worth exploring in-process · test fake

src/content/main.tsx (start) · src/content/get-focused-tweet.ts · consumes the controller's TargetResolver seam

Before — live targeting assembled inline, untested

The controller tests against a fake resolver — but the real targeting has no locality and no tests.

After — one targeting module, two adapters

The climb-out idiom lives once; the live adapter is now exercisable in tests, not just the fake.

Problem

The controller's TargetResolver seam is clean, but its production adapter — hover tracking, the quoted-tweet climb-out (copied again in caret-actions), the focused-tweet fallback, the caret-corner geometry — is assembled ad hoc inside main.tsx start() and has no test.

Solution

createTweetTargeting(document) owns the listeners and the resolution rules, and exposes author(), tweet(), anchorFor(), and the visualHover signal. main.tsx drops to wiring.

Wins
  • ▪ locality: "what is the user pointing at" in one module
  • ▪ the live adapter becomes the test surface, not just the fake
  • ▪ quoted-tweet climb-out defined once
  • ▪ main.tsx start() shrinks toward pure wiring
Deletion test: remove it → the climb-out, hover tracking, focus fallback, and anchor geometry scatter back into start() with no coverage. Concentrates the targeting knowledge — though today it has a single production caller, so the win is locality + testability rather than a second live adapter.
Top recommendation

Start with Candidate B — collapse the X HTTP transport

It is the safest, highest-certainty deepening: pure request logic behind a mockable fetch, with the backend contract test already pinning behaviour. It removes three copies of authHeaders and the drifted error mapping in one move, and fixes a real inconsistency — GraphQL rate-limits silently losing resetAt. Characterise the three transports with tests, route them through one xFetch seam, watch the same tests stay green.

Then take Candidate A — the highest-leverage win, but it touches the live-DOM and MAIN-world boundary, so let B prove the consolidation pattern first. Candidate C is the lighter follow-up.

No ADR conflicts — all three preserve the strategy seam (ADR-0001/0007), same-origin auth (ADR-0002), and the centralized Selectors table (ADR-0004).
